# KiliSpatial

Open-source 3D trekking viewer for **Mount Kilimanjaro**: seven routes, park gates, camps and huts, nearby lodging, elevation profiles and a cinematic fly-through, all on real terrain.

> **MVP. Not for navigation.** Trail geometry comes from OpenStreetMap and may have gaps or errors, itineraries are typical operator schedules, and weather and oxygen values are simulated estimates from altitude. Trek with a licensed guide and official maps.

## Features

- Full 3D terrain (MapLibre GL JS) with every route drawn on the mountain, or one route selected
- Routes: Marangu, Machame, Lemosho, Rongai, Umbwe, Shira and the Northern Circuit (`?route=machame`, `?route=all`)
- Real data: trails, gates, camps and huts from OpenStreetMap, elevations sampled from the terrain model
- Day-by-day itinerary per route with distance, ascent, descent and a camp orbit
- Click any gate, camp or hut for a detail card (elevation, position, which routes use it)
- Optional lodging layer: 100+ hotels, lodges and hostels near the gates, clustered
- Scrubbable elevation profile synced to the map, with vegetation zones and trail gaps marked
- "Walk the route" fly-through with live altitude, oxygen and weather readouts
- "Field journal" UI: warm paper and ink, serif display type, one ochre accent (Flowbite Svelte underneath)

## Stack

SvelteKit 3 · Svelte 5 (runes) · TypeScript · Tailwind CSS v4 · Flowbite Svelte · MapLibre GL JS · lucide-svelte · Fraunces + Instrument Sans (self-hosted via Fontsource) · pnpm

## Getting started

Requires Node 22.17+ and [pnpm](https://pnpm.io).

```sh
pnpm install
pnpm dev          # http://localhost:5173
pnpm check        # svelte-check, must stay at 0 errors / 0 warnings
pnpm build        # static SPA in ./build
pnpm build:data   # regenerate static/data from OpenStreetMap (see below)
```

## Data

The app reads static JSON from `static/data/`, generated by `pnpm build:data`:

| File | Content |
| --- | --- |
| `index.json` | one summary per route (name, days, distance, ascent, bbox) |
| `routes/<id>.json` | full route: polyline with elevation, days, stops, trail gaps |
| `places.json` | gates, camps, huts and summits with elevation and the routes that use them |
| `lodging.json` | hotels, lodges and hostels within 18 km of a park gate |
| `meta.json` | generation date, attribution and caveats |

How it is built (`scripts/`):

1. **OpenStreetMap** (Overpass API) provides the hiking-route relations, place positions and lodging. Responses are cached in `scripts/.cache`.
2. **Curated layer** (`scripts/curated.mjs`) says which OSM objects are the same camp, gives canonical names and defines the typical itinerary for each route. Everything curated is flagged.
3. Each day's path is a shortest path through the OSM trail graph between its stops. Where the trail data is broken, the builder bridges the break and records it as a **gap**, drawn dotted on the map and chart.
4. Elevations are sampled from the AWS Terrarium DEM (about 19 m), smoothed, then the path is simplified to about 8 m.

**Known limits**

- Gilman's Point and Stella Point are not in OSM and are not included until a verified GPS source is found.
- The Northern Circuit and Shira itineraries are marked *indicative*.
- Distances and ascent are computed from OSM geometry and a DEM, so expect a few percent error against published figures.

## Project layout

```
scripts/build-data.mjs         OSM + DEM -> static/data
scripts/curated.mjs            place matching and typical itineraries
src/lib/types.ts               shapes of the JSON data
src/lib/data/                  loader, Track (km <-> position/elevation), altitude estimates
src/lib/state/trek.svelte.ts   shared rune state (route, scrub, playback, camera commands)
src/lib/components/            Map3D, Sidebar, Masthead, StageSelector, PlaceCard, Readout, ElevationChart, ...
src/routes/layout.css          design tokens (paper, ink, ochre) and type
```
